# Tripo: Риггинг модели

Этот узел берёт существующую 3D-модель Tripo и создаёт её версию с ригом, то есть модель получает скелет, который позволяет её анимировать. Вы указываете ID задачи модели, для которой нужно создать риг, выбираете версию рига, тип скелета, стиль именования костей и формат выходного файла; узел отправляет задание в Tripo, ожидает его завершения, а затем возвращает загруженный результат.

## Входы

| Параметр | Описание | Тип данных | Обязательный | Диапазон |
|-----------|-------------|-----------|----------|-------|
| `идентификатор_задачи_исходной_модели` | ID задачи исходной 3D-модели, для которой нужно создать риг. Обычно это ID, полученный от предыдущего узла генерации модели Tripo. | MODEL_TASK_ID | Да | - |
| `model_version` | Версия модели для рига. v1.0: только гуманоидные (двухногие) персонажи, 90+ анимационных пресетов. v2.5: негуманоидные существа (четвероногие, шестиногие, восьминогие, птичьи, змеевидные, водные). По умолчанию: `v1.0-20240301`. | COMBO | Нет | "v1.0-20240301"<br>"v2.5-20260210" |
| `rig_type` | Тип скелета. "auto" сначала запускает бесплатную проверку возможности создания рига в Tripo и использует рекомендованный тип. По умолчанию: "auto". | COMBO | Нет | "auto"<br>"biped"<br>"quadruped"<br>"hexapod"<br>"octopod"<br>"avian"<br>"serpentine"<br>"aquatic" |
| `spec` | Именование костей: нативное Tripo или совместимое с Mixamo. Tripo не может выполнить ретаргетинг своих анимационных пресетов на риг v1.0, созданный со спецификацией mixamo; используйте `tripo` для Tripo: Retarget rigged model. По умолчанию: "tripo". | COMBO | Нет | "tripo"<br>"mixamo" |
| `out_format` | Формат выходного файла; результат поступает в соответствующий выход. По умолчанию: "glb". | COMBO | Нет | "glb"<br>"fbx" |

**Примечание:** Версия модели v1.0 (`v1.0-20240301`) поддерживает только двухногие скелеты. Если с этой версией используется `rig_type`, отличный от biped, узел вызывает ошибку и предлагает вместо этого использовать `v2.5-20260210`.

**Примечание:** Когда `rig_type` имеет значение "auto", Tripo сначала проверяет, можно ли создать риг для модели, и выбирает рекомендуемый тип скелета. Если Tripo сообщает, что для модели нельзя создать риг, узел завершается ошибкой.

**Примечание:** Узел ожидает, что Tripo вернёт файл GLB или FBX. Если Tripo возвращает файл любого другого типа, узел вызывает ошибку.

**Примечание:** Заполняется только выход, соответствующий `out_format`: `GLB`, когда `out_format` имеет значение "glb", и `FBX`, когда `out_format` имеет значение "fbx". Другой 3D-выход остаётся пустым.

## Выходы

| Имя выхода | Описание | Тип данных |
|-------------|-------------|-----------|
| `файл модели` | Имя сгенерированного файла модели с ригом (ID задачи плюс расширение формата). Оставлено только для обратной совместимости. | STRING |
| `task_id рига` | ID задачи для отслеживания процесса создания рига. | RIG_TASK_ID |
| `GLB` | Модель с ригом в виде 3D-файла GLB. Заполняется, когда `out_format` имеет значение "glb". | FILE3DGLB |
| `FBX` | Модель с ригом в виде 3D-файла FBX. Заполняется, когда `out_format` имеет значение "fbx". | FILE3DFBX |

# モデルのブロックスパースアテンション

## 概要

ブロック稀疏注意力ノードは、ComfyUIモデルにブロック稀疏注意力メカニズムを適用するために使用されます。このメカニズムは、各クエリブロックが全ての可能性のあるブロックではなく、キーブロックの一部にのみ焦点を当てることを許可することで、計算負荷を削減します。これは特に長いシークエンスに対して非常に有益です。

## 入力

| パラメータ | 説明 | データ型 | 必須 | 范囲 |
|------------|------|---------|------|-------|
| `model` | ブロック稀疏注意力を適用するComfyUIモデル | MODEL | はい | N/A |
| `selection` | キーブロックの選択に使用される方法 | DYNAMIC_COMBO | はい | オプション: sol-attn (適応型tau), sla (top-k), vsa (Video Sparse Attention) |
| `tau` | sol-attnメソッドのスコア分布シグマの閾値 | FLOAT | いいえ | デフォルト: 1.3, 最小: 0.0, 最大: 4.0, ステップ: 0.05 |
| `keep_percent` | slaメソッドの各クエリブロックが正確に保持するキーブロックの割合 | FLOAT | いいえ | デフォルト: 10.0, 最小: 0.5, 最大: 95.0, ステップ: 0.5 |
| `start_percent` | 稀疏注意力が開始する百分率ポイント | FLOAT | いいえ | デフォルト: 0.2, 最小: 0.0, 最大: 1.0, ステップ: 0.01 |
| `end_percent` | 稀疏注意力が終了する百分率ポイント | FLOAT | いいえ | デフォルト: 1.0, 最小: 0.0, 最大: 1.0, ステップ: 0.01 |
| `dense_blocks` | 常に稠密注意力を使用するトランスフォーマーブロックを表す文字列 | STRING | いいえ | デフォルト: "" |
| `min_tokens` | モデルが稠密注意力を使用するシークエンスのトークン数の最小値 | INT | いいえ | デフォルト: 12288, 最小: 0, 最大: 1 << 20, ステップ: 512 |
| `extra_tokens` | 各クエリブロックが選択したブロックを超えて注目する最高評価トークンの数 | INT | いいえ | デフォルト: 256, 最小: 0, 最大: 256, ステップ: 64 |
| `sink_conditioning` | 使用するMiniMax-H3の条件行のMiniMax-H3条件 | COMBO | いいえ | オプション: exact_kv, exact_kv_and_rows, off |
| `verbose` | 詳細なログ出力を有効にします | BOOLEAN | いいえ | デフォルト: False |

### 注意事項

- `selection`パラメータを使用して、キーブロックの選択方法を選択できます：
  - `sol-attn`: スコア分布に基づいて適応型閾値を使用してキーブロックを選択します。
  - `sla`: 最高評価のキーブロックの固定割合を保持します。
  - `vsa`: Video Sparse Attentionを適用し、3Dビデオキューブタイルと学習済みの粗い注意力ブランチを使用します。
- `dense_blocks`パラメータを使用して、常に稠密注意力を使用するトランスフォーマーブロックを指定できます。
- `min_tokens`パラメータは、稠密注意力が使用されるシークエンスのトークン数の最小値を設定します。
- `extra_tokens`パラメータを使用して、各クエリブロックが注目する追加の最高評価トークンの数を指定できます。
- `sink_conditioning`パラメータは、MiniMax-H3モデルにのみ関連しており、条件行の処理方法を決定します。
- `verbose`パラメータは、詳細なログ出力を有効にし、デバッグに役立ちます。

## 出力

| 出力名 | 説明 | データ型 |
|--------|------|---------|
| `model` | ブロック稀疏注意力が適用されたComfyUIモデル | MODEL |

### 制約と制限

- `sol-attn`メソッドは、0.0から4.0の間の`tau`値が必要です。
- `sla`メソッドは、0.5から95.0の間の`keep_percent`値が必要です。
- `vsa`メソッドは、MiniMax-H3モデルと互換性があり、モデルに`to_gate_compress`レイヤーがある必要があります。
- `min_tokens`パラメータは、0以上の整数である必要があります（0に設定するとすべてのアテンションが密になります）。
- `extra_tokens`パラメータは、非負の整数でなければなりません。
- `sink_conditioning`オプションは、MiniMax-H3モデルにのみ適用されます。

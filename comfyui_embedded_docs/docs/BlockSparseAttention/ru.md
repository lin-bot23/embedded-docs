# Блочно-разреженное внимание модели

## Обзор

Узел Block Sparse Attention модифицирует модель ComfyUI для применения механизма блок-спарсинга внимания. Этот механизм уменьшает вычислительную нагрузку, позволяя каждому блоку запроса фокусироваться на подмножестве блоков ключей, а не на всех возможных блоках, что особенно полезно для длинных последовательностей.

## Входы

| Параметр | Описание | Тип данных | Обязателен | Диапазон |
|-----------|-------------|-----------|----------|-------|
| `model` | Модель ComfyUI, к которой применяется блок-спарсинг внимания. | MODEL | Да | N/A |
| `selection` | Метод, используемый для определения, какие блоки ключей следует учитывать. | ДИНАМИЧЕСКАЯ КОМБО | Да | Опции: sol-attn (адаптивный tau), sla (top-k), vsa (Video Sparse Attention) |
| `tau` | Порог в сигмах распределения оценок для метода sol-attn. | ФЛОАТ | Нет | по умолчанию: 1.3, мин: 0.0, макс: 4.0, шаг: 0.05 |
| `keep_percent` | Процент блоков ключей, которые каждый блок запроса сохраняет точно для метода sla. | ФЛОАТ | Нет | по умолчанию: 10.0, мин: 0.5, макс: 95.0, шаг: 0.5 |
| `start_percent` | Процентный пункт, когда начинается спарсинг внимания. | ФЛОАТ | Нет | по умолчанию: 0.2, мин: 0.0, макс: 1.0, шаг: 0.01 |
| `end_percent` | Процентный пункт, когда заканчивается спарсинг внимания. | ФЛОАТ | Нет | по умолчанию: 1.0, мин: 0.0, макс: 1.0, шаг: 0.01 |
| `dense_blocks` | Строка, представляющая трансформаторные блоки, которые всегда используют сплошное внимание. | STRING | Нет | по умолчанию: "" |
| `min_tokens` | Минимальное количество токенов в последовательности, для которой модель использует сплошное внимание. | ИНТ | Нет | по умолчанию: 12288, мин: 0, макс: 1 << 20, шаг: 512 |
| `extra_tokens` | Количество дополнительных топ-оценочных токенов, которые каждый блок запроса учитывает сверх своих выбранных блоков. | ИНТ | Нет | по умолчанию: 256, мин: 0, макс: 256, шаг: 64 |
| `sink_conditioning` | Строки MiniMax-H3 для использования в sink conditioning. | КОМБО | Нет | Опции: exact_kv, exact_kv_and_rows, off |
| `verbose` | Включает подробное логирование. | MODEL | Нет | по умолчанию: False |

### Замечания

- Параметр `selection` позволяет выбрать между различными методами для выбора блоков ключей:
  - `sol-attn`: Использует адаптивный порог для выбора блоков ключей на основе распределения оценок.
  - `sla`: Сохраняет фиксированный процент самых высокооцененных блоков ключей.
  - `vsa`: Применяет Video Sparse Attention, который использует тiling 3D видео-куб и обученный粗ый ветвь внимания.
- Параметр `dense_blocks` можно использовать для указания трансформаторных блоков, которые всегда должны использовать сплошное внимание.
- Параметр `min_tokens` устанавливает минимальное количество токенов в последовательности, для которой используется сплошное внимание.
- Параметр `extra_tokens` позволяет указать количество дополнительных топ-оценочных токенов, которые каждый блок запроса должен учитывать.
- Параметр `sink_conditioning` относится только к моделям MiniMax-H3 и определяет, как обрабатываются строки conditioning.
- Параметр `verbose` включает подробное логирование, которое может быть полезно для отладки.

### Ограничения и ограничения

- Метод `sol-attn` требует значения `tau` между 0.0 и 4.0.
- Метод `sla` требует значения `keep_percent` между 0.5 и 95.0.
- Метод `vsa` совместим только с моделями MiniMax-H3 и требует, чтобы модель имела слой `to_gate_compress`.
- Параметр `min_tokens` должен быть неотрицательным целым числом (при 0 всё внимание остаётся плотным).
- Параметр `extra_tokens` должен быть неотрицательным целым числом.
- Опции `sink_conditioning` относятся только к моделям MiniMax-H3.
